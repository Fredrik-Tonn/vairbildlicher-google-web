# Analyse und Testergebnisse – 23.09.2026

> **Einordnung:** Dieses Repository ist eine **Technikprobe** für einen Hackathon mit Google und der Aktion Mensch.
> Die Technikprobe prüft, ob sich im laufenden Chat **Bilder in Echtzeit** als Verständnishilfe erzeugen lassen.
> Das Projekt ist **keine neue Version und keine Erweiterung des Verainfachers**.
> Deshalb bewertet diese Analyse das Projekt am Hackathon-Ziel und nicht an Maßstäben für den Produktivbetrieb.

Stand des Codes: Commit `b7b3b1a` („initiales Projekt-Setup …“), Branch `main`.

---

## 1. Was die Technikprobe heute kann

- Sie nimmt Fotos von Dokumenten auf.
  `gemini-3.8-flash` fasst den Text in Leichter Sprache zusammen.
- Sie erzeugt Folgefragen, schwierige Wörter und ein Multiple-Choice-Quiz.
- Sie erzeugt ein Bild zur Antwort, den „Verbildlicher“.
  Das Bild entsteht nur auf Knopfdruck unter jeder KI-Antwort
  (`ChatBubble.svelte` → `POST /api/visualize` → `gemini-3.1-flash-image`).
- Sie gibt Text als Sprache aus (Google Cloud TTS, Stimme `de-DE-Neural2-B`).

Aufbau, Quiz, Punktesystem und System-Prompts stammen aus der älteren Verainfacher-Codebasis.
Neu ist die Umstellung auf die Google-APIs (`@google/genai` 2.24 mit der Interactions-API) und die Bilderzeugung.

### Bewertung der Wartezeit

- Wenn die Person nach der Antwort auf den Bild-Knopf tippt, wartet sie noch einmal **10–11 Sekunden**.
- Wenn das Bild automatisch startet, kommt es insgesamt etwa **17 Sekunden** nach dem Absenden.
- Echtzeit im engeren Sinn ist das nicht.
  Die Technikprobe braucht deshalb eine klare Ladeanzeige oder eine Vorab-Erzeugung.

### Das Testbild

Testsatz: „Sie müssen den Antrag bis zum 30. Oktober beim Jobcenter abgeben.“
Der Satz lief mit dem aktuellen Bild-Prompt aus `gemini.service.ts`.

![Testbild](befunde/2026-09-23_testbild_jobcenter.jpg)

Befunde zum Bild:

1. **Text trotz Verbot:** Der Prompt enthält „no text inside the image“.
   Das Bild enthält trotzdem einen Kalender, „DEADLINE/ABGABEFRIST“ und zweimal „jobcenter“.
2. **Falsche Angaben:** Das Bild zeigt das Jahr 2024 und falsche Wochentage („MON DIO MI DIO FRI“).
   Für die Zielgruppe ist das gefährlich, weil das Bild eigene Fakten dazuerfindet.
3. **Ähnlichkeit mit einem echten Logo:** Das Logo ähnelt dem der Bundesagentur für Arbeit.
4. **Zu voll für die Zielgruppe:** Pflanzen, Uhr, Pinnwand und Sessel lenken von der eigentlichen Aussage ab.

**Folgerung:** Die Qualität der Bilder hängt vor allem am Bild-Prompt.
Die Technikprobe braucht einen eigenen Bild-Prompt mit Regeln für die Bildsprache:
ein Motiv, keine Schrift, keine Zahlen, keine Logos, ein einheitlicher Stil.
Diese Regeln werden aus den Befunden dieses Projekts und der Zielgruppe entwickelt.
Der Bildprompt aus dem Projekt AInfach ist dafür **nicht** geeignet, weil er für ein anderes Problem gedacht ist (Entscheidung 23.09.2026).

## 4. Befunde zum restlichen Code

### Wichtig für die Demo

1. **Sprachausgabe gesperrt:** Ohne `GOOGLE_TTS_API_KEY` nutzt der Code den `GEMINI_API_KEY` auch für Cloud TTS.
   Für den Hackathon-Schlüssel ist Cloud TTS gesperrt.
   Es gibt zwei Lösungen:
   - Die Cloud Text-to-Speech API im Google-Cloud-Projekt freischalten und für den Schlüssel erlauben.
   - Die Sprachausgabe auf Gemini-TTS umstellen.
     `gemini-3.8-flash-tts` ist mit dem Schlüssel verfügbar.
2. **Datenschutz:** Fotos von Behördenpost gehen an die Gemini-API.
   Mit einem kostenlosen Schlüssel aus Google AI Studio darf Google die Daten zum Verbessern der Modelle nutzen.
   Deshalb nur Beispieldokumente verwenden oder den bezahlten Zugang oder Vertex AI in der EU nutzen.
3. **Keine Verkleinerung der Fotos:** Fotos gehen unverkleinert als Base64 an den Server.
   `BODY_SIZE_LIMIT` ist 50 MB.
   Große Handyfotos verlängern die Wartezeit auf die Antwort und damit auch auf das Bild.
4. **Schlüssel in der URL:** Der TTS-Aufruf überträgt den Schlüssel als URL-Parameter (`?key=`).
   Das Gemini-SDK überträgt ihn im Header.

### Typ-Prüfung (`npm run check`): 9 Fehler, 6 Warnungen

- `ChallengeOverlay.svelte:137`: `addChallengePerformanceReward(correctCount)` bekommt nur ein Argument, `totalQuestions` fehlt.
  Die Punkte-Meldung enthält dann vermutlich „undefined“.
- `redis.adapter.ts`: 3 Typ-Fehler (Typ des Redis-Clients, möglicher `null`-Wert).
- `src/lib/server/db/data.ts`: 5 Fehler, denn in den Beispieldaten fehlt das Feld `words`.
- Warnungen: veraltetes `<svelte:component>`, doppelte `role="banner"`, ungenutztes CSS.

### Widersprüche zwischen Doku und Code (in PROJEKT.md korrigiert)

- **Prompt-Cache:** Laut Doku leert sich der Cache nach 30 Minuten.
  Der Code speichert die Prompts aber **ohne Ablaufzeit**.
  Mit Redis wirken geänderte `.txt`-Dateien erst, wenn jemand die Schlüssel `vair:prompts:*` löscht.
  Ohne Redis wirken sie erst nach einem Neustart.
- **Bildmodell:** Laut Doku „Imagen 3“, tatsächlich das Gemini-Bildmodell `gemini-3.1-flash-image`.
- **Web Speech API als Ersatz für die Sprachausgabe:** Gibt es nur im statischen Mockup (`app.js`), nicht in der SvelteKit-App.
- **README:** Beschreibt nur das statische Mockup, nicht die SvelteKit-App.

### Kleinere Punkte, für die Technikprobe nachrangig

- Das Repo enthält zwei Apps: die SvelteKit-App und ein statisches Material-Design-Mockup (`index.html`, `app.js`, `styles.css`, `manifest.json`).
- Der Name wechselt: *vairbildlicher* (Repo), *verbildlicher-web* (`package.json`), *Verbildlicher* (Seitentitel), *Verainfacher* (Doku).
- Es gibt keine Begrenzung der Anfragen, auch nicht für die Bilderzeugung.
- Die Testseiten `/test` und `/overlay-test` sowie der ungenutzte Endpunkt `/api/getfile` würden mit veröffentlicht.
- `polly.service.ts` ist leer.
  `chat.service.ts` gibt nur `gemini.service.ts` weiter.
- Schwierige Wörter:
  - Der Prompt verlangt 5 Wörter, der Code übernimmt bis zu 6.
  - Der Code verwirft jedes Wort, das „keine“ enthält.
  - Er prüft nicht, ob die Wörter im Text vorkommen.
- Der Code lädt die System-Prompts relativ zum Arbeitsverzeichnis (`local-files/system-prompts`).
  Deshalb muss `node build` im Hauptordner des Repos starten.

## 5. Vorgeschlagene nächste Schritte für die Technikprobe

1. Die Sprachausgabe auf Gemini-TTS (`gemini-3.8-flash-tts`) umstellen.
   Die Alternative ist, Cloud TTS in der Console freizuschalten.
2. Einen eigenen Bild-Prompt als `.txt` anlegen, zum Beispiel `local-files/system-prompts/ImageSystemPrompt.txt`.
   Er soll eigene Bildregeln aus den Befunden oben enthalten und über `loadSystemPrompts()` geladen werden.
3. Das Bild automatisch nach der Antwort erzeugen, so wie Folgefragen und schwierige Wörter in `ChatFlow.svelte`.
   Dazu eine Zeitmessung und eine Ladeanzeige einbauen.
4. Ein Bild pro Satz über `ClickableSentences` anbieten.
   So lassen sich im Hackathon zwei Varianten vergleichen: ein Bild pro Antwort und ein Bild pro Satz.
5. Handyfotos vor dem Hochladen verkleinern.
